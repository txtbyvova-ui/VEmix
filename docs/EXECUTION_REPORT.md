# VEgroove Automix 2.0 — отчёт о выполнении (ТЗ `ТЗ/task_01.md`, §16)

Дата: 2026-10-19. Ветка: `feature/automix-2.0` (локально, не закоммичено и не запушено).
Окружение проверки: Windows 11, Python 3.12.10 (`.venv`), FFmpeg/ffprobe 9.0.2 (Gyan full build).

## 1. Сводка изменений

Монолитный `automix.py` (708 строк) разобран на пакет `veg_mixer/` (~14 000 строк) с тестами
(~7 900 строк). Исходный прототип сохранён без изменений в `legacy/automix_v1.py` — его функции
BPM/тональности используются регрессионными тестами (тональность не должна меняться — правило
из памяти проекта). Что переиспользовано из v1: алгоритмы `detect_bpm`/`detect_key` (бит-в-бит,
с исправлением падения на треках < 30 с в librosa 1.0), правила колеса Camelot, обрезка тишины,
формат трек-листа (первые колонки совместимы), идея md5-сида и `--parts`.

Реализовано по фазам ТЗ:

| Фаза | Что сделано |
|------|-------------|
| 1 | `loudness.LoudnessNormalizer`: двухпроходный EBU R128 `loudnorm`, валидация JSON FFmpeg, план (linear / peak-limited / opt-in dynamic), lossless WAV-промежуточный, одно MP3-кодирование, проверка **закодированного** MP3 (LUFS, true peak, длительность, каналы, частота, полное декодирование), коррекция в замкнутом контуре из WAV, атомарная публикация |
| 2 | `playlist`: отдельные нормализованные MP3 (`NNN_Artist_Title.mp3`), `playlist.m3u8` (EXTINF, относительные пути, UTF-8), `manifest.json`, `tracklist.txt`; транзакционная публикация с откатом; `quality_control` + `reports` (JSON + TXT, сводка §11) |
| 3 | `models.TrackFeatures` + источники/уверенность признаков; `metadata` (CSV/JSON куратора, ручные значения главнее); `curation` (профиль YAML/JSON, языки, кириллица, block/allow-листы, предпочтения, дейпарты); `sequencing` (взвешенные компоненты с учётом неизвестного, beam search, жёсткие ограничения, дейпарты) |
| 4 | `transitions` + `renderer` (потоковый рендер RF64, FX только на копии хвоста уходящего трека, кривые, защита пиков перекрытия ×4 oversampling, учёт длительности); `cache` (отпечаток файла + версии/параметры секций, атомарная запись, восстановление, миграция v1 только на чтение) |
| 5 | CLI `analyze/normalize/playlist/mix/qc` + старый синтаксис v1, `--dry-run`, прогресс, коды выхода; README, ARCHITECTURE, демо-генератор, скрипт замеров, пример отчётов |

Ключевые инженерные решения:
* **True peak важнее LUFS.** Если цель достижима только лимитированием: недобор в пределах ±1 LU
  выдаётся линейно (PASS), больше — линейно и безопасно по пику со статусом **review**.
  Динамический режим `loudnorm` оказался не «лимитером», а AGC всего трека — он выключен
  по умолчанию (`--max-dynamic-gain` — явное включение, всегда с пометкой на ревью).
* Учтена особенность `loudnorm` (FFmpeg 9.0.2): при `measured_LRA = 0` он молча уходит в
  dynamic — передаётся 0.01 LU; фактический режим из JSON второго прохода фиксируется.
* Одна реализация правил: `textnorm.py` (теги, артисты, языки, пути); QC проверяет исключения,
  повторно вызывая `curation.curate`.
* Никогда «PASS при сбое»: проваленный трек → `Tracks failed` и FAIL; неопубликованный микс → FAIL;
  пропущенная критичная проверка не даёт PASS; категория, не проверявшаяся в режиме, печатается
  как `n/a`, а не 0.
* Защита исходников: все запланированные выходы сверяются со всеми найденными исходниками ДО
  работы; свои прошлые выходы не попадают в сканирование.

## 6. Известные ограничения

* Нет детекции долей/фраз; переходы не выравниваются по сетке — при заметной разнице темпов или
  неизвестном BPM кроссфейд укорачивается и помечается «listen».
* Авто-«энергия» — эвристика, проверенная только на синтетике (уверенность 0.4); настроение,
  жанр (кроме ID3), язык (кроме тегов) и «узнаваемость» автоматически не определяются.
* Дейпарты не имеют отдельных правил стилистической преемственности (см. README); вытесненный
  «спокойным стартом» трек не возвращается в свой дейпарт (EDIT-11).
* На патологическом контенте (щелчки на тихой подложке) `loudnorm` и `ebur128` расходятся до ~1 LU
  (помечается предупреждением).
* Не проверено: полный 3.5-часовой микс (RF64 и потоковый рендер проверены на коротких файлах;
  память ≈230 МБ на 29-минутном миксе), macOS/Linux, сетевые диски, реальная коммерческая музыка,
  **прослушивание** переходов и FX человеком.

## 7. Что требует ручной курации

* Язык треков без тега (особенно кириллица в названии — по умолчанию исключается до подтверждения).
* Настроение, жанр, теги атмосферы, энергия (авто-оценка грубая), «узнаваемость» (никогда не
  выдумывается), одобрение треков (`approved`), исключения.
* Решения по трекам со статусом **review** (не достигают цели громкости без сильного лимитирования).
* Прослушивание помеченных переходов («listen», скачки энергии, громкость на стыке) и тихих
  мест/пауз из отчёта QC.
* Числовые параметры дейпартов в `profiles/client.yaml` — редакционные отправные точки.

## 9. Как проверялась работа

1. Фаза 1 написана и проверена отдельно (44 теста на реальном FFmpeg), затем 6 модулей фаз 2–4
   реализованы параллельно по контрактам `docs/ARCHITECTURE.md`.
2. Адверсариальное ревью по 5 направлениям (соответствие ТЗ, DSP, сохранность данных, интеграция,
   редакционная логика) с независимым верификатором: **68 подтверждённых находок** (5 critical,
   11 high), 5 опровергнуто. Критичные: `mix --output` мог перезаписать исходник, `normalize` мог
   перезаписать чужой исходник, ложный PASS при проваленном треке/неопубликованном миксе.
3. Исправления + два раунда повторной верификации со скептиками (воспроизведение каждой находки на
   новом коде): закрыты все, кроме трёх сознательно оставленных low-ограничений (EDIT-11, EDIT-15 —
   задокументированы; VEDIT-3 — формулировка исправлена).

Предложено, но не реализовано (возможные следующие шаги): детекция фраз/долей для выравнивания
переходов; правила стилистической преемственности по дейпартам; калибровка эвристики энергии на
реальной разметке куратора; веб-плеер поверх `manifest.json`; прогон на реальной библиотеке клиента
